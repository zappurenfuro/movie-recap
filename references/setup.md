# First installation

This is an agent workflow. A person may simply paste the repository URL and ask you to install it. Complete these steps without starting a film render.

1. Inspect README.md, install.py, runtime_setup.py and requirements-runtime.txt. Clone/download into an unused folder; do not overwrite a user's checkout. Check available Python and the requested host. Read-only inspection is fine before permission.
2. Show the installation plan before installing: supported 64-bit Python 3.11–3.13; isolated virtual environment; every pinned package from requirements-runtime.txt (NumPy, Pillow, PyAV, imageio-ffmpeg, kokoro-onnx, ONNX Runtime, faster-whisper, huggingface-hub); their transitive packages; FFmpeg; Kokoro ONNX and voice data; multilingual Whisper base and English base.en models. Explain that exact transitive versions depend on resolution. Show actual destinations, upstream download services, roughly 3 GB setup space plus media workspace space, CPU default, and no paid service or CUDA installation. `python install.py --dry-run` prints the plan without downloads or writes. Do not claim this installer installs Python itself.
3. Ask: “May I install these dependencies, models and the skill in the locations above?” Wait for the answer. If Python, Git or an OS venv component is missing, include its proposed installation in the plan and obtain permission before changing the system. ZIP installation does not require Git. Never silently request administrator access.
4. Separately ask: “Would you like automatic publishing to your YouTube channel after each verified recap, or local files only?” Explain that YouTube means full videos plus narrated vertical Shorts; Instagram is a separate optional connection. Default to local output if declined. Do not assume an answer from silence.
5. After both answers, run the appropriate approved command, such as `python install.py --target codex --yes --publishing local` or `python install.py --target claude --yes --publishing youtube`. Use `--target both` only when requested. `--yes` records already-obtained installation consent; agents must not add it to bypass step 3. The publishing flag must reflect the user's separate answer. Interactive users can run without flags and answer the two prompts. `--skill-only` is an explicit alternative, not a successful full setup.
6. Require successful runtime checks and inspect the ready manifest and referenced paths. Report failures precisely and reuse completed downloads on retry. Do not invent a successful install based on file existence. Reopen the host session if needed for skill discovery.
7. If YouTube was chosen, continue [publishing onboarding](publishing.md): open Studio and hand off sign-in. The installer records only `youtube_pending_signin`; it does not sign in, pick an account or publish. If no browser tool is available, explain that connection remains pending and provide the Studio link.
8. Report installed targets, verification results, publishing state and invocation: Claude Code `/movie-recap "film or path"`; Codex `$movie-recap "film or path"`. The source movie remains user-supplied. No render or test upload is part of setup.

## Updates and private settings

Use `--update` to back up differing installed skill files. Existing `.movie-recap/setup.json` or `publishing.md` settings are preserved when `--publishing` is omitted. New installation permission still applies to changed dependencies; do not repeatedly ask to connect accounts already explicitly authorized. For project installs, prefer project-local settings; otherwise use the user's home settings. Never copy either settings file, runtime manifests, account data or backup copies into the public repository.

An explicit `--publishing local` disables standing automatic uploads without deleting older preferences. `--publishing youtube` requires completing sign-in/channel confirmation before automatic publishing. Turning publishing off must not sign users out, delete posts or revoke credentials without a separate request.
